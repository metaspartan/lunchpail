# M1 Ultra end-to-end canary — 2026-08-11

This is a research canary for one host, guest, and workload. It demonstrates
that Lunchpail's narrow capability profile changes llama.cpp's kernel selection
and materially improves performance. It does not establish that arbitrary
Metal workloads are compatible with the profile.

## Environment

- host: Apple M1 Ultra, 64 GPU cores, 128 GiB unified memory
- host OS: macOS 27.0 build `26A5378n`
- guest: macOS 26.5.2 build `25F84`, 8 vCPU, 64 GiB
- virtual GPU: `Apple Paravirtual device`
- VM image: `ghcr.io/trycua/macos-tahoe-cua:latest`
- image manifest: `sha256:ed1783e80e08e888889b54a8c0387105a37fbcfc995079f76db48e2280081487`
- llama.cpp: b10359, commit `84f712946`
- llama.cpp archive SHA-256: `8eb447e8e972fff6818ea9ac7db9af270ee1d4ced46d2a7eaf918a5a0c0c8ffe`
- model: TinyLlama 1.1B Chat v1.0 Q4_K_M
- model SHA-256: `9fecc3b3cd76bba89d504f29b616eedf7da85b96540e490ca5824d3f7d2776a0`

## Capability canary

| Answer | Stock guest | Profiled process |
|---|---:|---:|
| Apple family 9 | false | true |
| maximum threadgroup memory | 32,768 B | 65,536 B |
| Metal 3 | false | false |
| recommended working set | unchanged | unchanged |

The profiled llama.cpp process consequently reported SIMD-group reduction,
SIMD-group matrix multiplication, and bfloat16 support. The stock process did
not. Residency sets remained enabled in both runs.

## Command

Both guest runs used:

```bash
./llama-b10359/llama-bench \
  -m ./tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf \
  -p 512 -n 128 -r 3 -t 8 -ngl -1 -o json
```

The profiled run added only:

```bash
DYLD_INSERT_LIBRARIES="$HOME/lunchpail-bench/libLunchpailMetalShim.dylib"
LUNCHPAIL_METAL_APPLE_FAMILY_MAX=1009
LUNCHPAIL_METAL_MAX_THREADGROUP_MEMORY=65536
```

## Results

| Work | Stock guest | Profiled guest | Speedup | Bare host | Guest/host |
|---|---:|---:|---:|---:|---:|
| prompt, 512 tokens | 396.819 tok/s | 5,122.031 tok/s | 12.908× | 5,163.840 tok/s | 99.19% |
| generation, 128 tokens | 8.064 tok/s | 167.363 tok/s | 20.754× | 250.947 tok/s | 66.69% |

The figures are arithmetic means of the three samples emitted by
`llama-bench`. First-load Metal compilation was outside the reported throughput
measurements. The stock and profiled guest runs used the same VM allocation,
binary, model, arguments, and disk copies.

## Runtime and cleanup checks

Lunchpail imported the existing VM without copying its disk, validated the
generated Apple Virtualization configuration, and booted it headlessly. SSH on
the guest became reachable, the guest reported macOS 26.5.2, and a guest-driven
shutdown caused `lunchpail vm run` to exit cleanly. The private host preference
was restored to its original absent state and the recovery journal was removed.

Re-run this canary after every host OS, guest OS, Xcode/Metal compiler,
llama.cpp, or profile change. A capability probe alone is not enough to promote
a combination to supported status.
